# Firestore quota audit — 2026-11-02

Project: `propbank-944fc`, database `(default)`.

Targeted reductions implemented; **daily quota recovery is not verified**. No live Firestore reads, writes, load tests, deployment, Playwright, full suite or push were performed. The supplied ~50,000/day figure is user-reported, not measured by this audit. Static inspection cannot attribute the actual daily total to a particular endpoint, user, developer or scheduler.

## Evidence and accounting

`node scripts/audit-firestore-reads.cjs` generates `backend-audit/firestore-read-inventory.json`: a conservative, line-addressed inventory of calls throughout application source, scripts and tests. It records generic `.get()` calls too: Map, URLSearchParams, Headers and test HTTP calls are explicitly candidates, not database reads. It never imports the app or initializes Firebase. Historical audit exports, `.history`, generated output, dependencies and caches are not additional running consumers. Repository searches also covered imports, query helpers, timers, invalidation, listener cleanup and scheduler routes.

Application Firestore access is through server Admin SDK (`firestore.ts` / `firebase-admin.ts`). Browser Firebase initialization is Auth only. No active browser Firestore `getDoc`, `getDocs`, `onSnapshot`, collection-group query or aggregation consumer was found. Transaction reads and helper-based `getRecords`, `readObject`, `getProperty`, `getUser` calls remain important even when route files contain no `.get()` themselves.

Estimates below count returned documents, with a floor of one per executed query. Document gets, including missing documents, are budgeted as one. These are **not actual billed reads**: retries, transaction reruns, index-entry charges and other project consumers can differ. Admin SDK authorization remains authoritative on every server request; no persistent server authorization cache was added. See [Firestore billing](https://firebase.google.com/docs/firestore/pricing).

Notation: `P` = all properties; `A` = approved properties; `O` = properties owned by the viewer; `U` = users; `N` = notifications; `R` = archived notifications; `D` = documents for a property; `Dt` = matching document type; `H` = authorized hub properties (at most 250 processed, although initial scan is unbounded); `X` = their related records; `E` = email deliveries; `V` = visits. Apply minimum query charges separately when a symbol is zero. Auth profile reads are included where indicated; Auth SDK token verification itself is not counted as a Firestore document read.

## Confirmed multipliers and implemented reductions

| Operation | Before | After | Change / limits |
|---|---|---|---|
| Manage Property cold load, ordinary account | Two requests: approximately `2 + max(1,O) + 2*max(1,P)` | One request: `1 + max(1,O) + max(1,P)` | Owner endpoint already merges authorized tenant rows. Browser now uses its `userRole` projection. Saves one full tenant scan and one authorization profile read. Agent submission query remains additional. |
| Manage Property focus / remount | Every focus or remount repeats above | No refetch while fresh for 60s | Mutations still invalidate; stale focus/navigation still fetches. Failed query is not automatically retried. |
| Property Hub focus / navigation | Always stale; default retries | Fresh for 60s; no automatic retry | Existing batching is preserved. Initial property scan remains. |
| Admin property focus / remount | `1 + max(1,P)` each time | Zero during 60s freshness window | No forced mount/focus refetch; authorized mutations invalidate. |
| Admin Portal initial Properties tab | Also reads `1 + max(1,U)` for user directory | Zero user-directory reads | Directory enabled only on Agents tab. Its separate imperative tab-entry refetch was removed. |
| Admin refresh event while on Agents | Automatic cache invalidation plus imperative directory refetch | Cache invalidation only | Notifications/settings events no longer reload unrelated active tabs or the property dialog. |
| Visit history page | Public property list: `max(1,A)+1` settings read, even without opening form | Zero property-picker reads until form opens | Picker shares `publicProperties/home` with landing page; concurrent observers deduplicate; 60s freshness. Visit list still loads. |
| Archived notifications | `1 + max(1,N)` | `1 + max(1,R)` | `unread=false` adds server equality filter after admin authorization. Archive tab already displayed only read notifications. |
| Documents with documentType | `2 + max(1,D)` | `2 + max(1,Dt)` | Property membership and document type enforced before results; type filter moved into query. Unfiltered attachment lists unchanged. |
| Pending Connections idle with pending requests | 120 list refreshes/hour/tab | 30/hour/tab | 30s → 120s fallback polling. Focus still refreshes stale data (30s freshness); manual and mutation refresh retained. No pending rows → no interval. Other-device update latency can now be up to two minutes. |
| Refresh broadcast into hidden React Query tab | Immediate active-query refetch | Mark stale without immediate refetch | Next visible stale focus/mount refreshes. Visible in-flight query is not cancelled/restarted by another broadcast (`cancelRefetch:false`). |

Illustration, **not observed production cardinalities**: with 1,000 properties and 10 owned records, cold Manage Property drops from about 2,012 to 1,011 reads. Fifty cold loads would save about 50,050 document reads. That shows why removing a single duplicate scan matters; it does not prove this was the historical daily source.

Pending Connections executes two queries for each of 11 canonical/legacy statuses: **22 queries per list**, plus auth, throttle transaction, candidate state checks and owner property reads. Merely budgeting 22 query minimums, eight hours with continuously pending rows drops from 21,120 to 5,280 reads per tab (75% fewer timer-triggered list requests). Real cost is higher where queries return records. Discovery is separate and can run up to five bounded pages on identity initialization; it is not performed by every timer tick. Existing authorization/expiry logic was preserved.

## Refresh and development findings

React Query deduplicates concurrent observers sharing a key. The Visit Planner now uses the landing-page list key rather than an independent request. Auth profile in-flight dedup was retained. Refresh domains are broad: a document mutation still invalidates properties/relationships indirectly, and several forms explicitly refetch after `apiFetch` already publishes an event. These residual duplicate reads are not claimed fixed universally. Hidden-tab suppression applies to the central React Query bridge; imperative `useDataRefresh` consumers can still run in hidden tabs. BroadcastChannel is not a shared cross-tab data cache. Several open visible tabs can each refetch. Domain-to-query mapping remains broad, without record-ID scoping.

`subscribeDataRefresh` removes local, storage and channel listeners on unsubscribe. No active Firestore snapshot listener leak was found. Visit load effects abort on cleanup; property picker now uses Query observers. Landing's 10s interval only rotates images and performs no Firestore requests. Auth's 10m private-file session renewal is not a collection poll, though session/probe authorization may read profiles. Pending polling is conditional and stops without pending rows; it was reduced based on its confirmed 22-query fanout, not by redoing previous state/security fixes.

Local `.env.local` sets `FIREBASE_DATA_PROJECT_ID=propbank-944fc` and does not set `FIRESTORE_EMULATOR_HOST`. Default server fallback is also that production project. Thus ordinary `npm run dev` can access production Firestore when credentials work. Browser Auth emulator configuration alone does not redirect server Firestore. `.env.production` does not provide an emulator override in the inspected keys. Shell-level overrides and already-running process environments cannot be inferred from these files. Four running Node processes matched Next runtime/development commands; no Java emulator process was observed. That is a process snapshot, not proof of database traffic. No processes were stopped and no environment file was changed.

Use the existing `npm run dev:emulator` path for future local testing. `auth-emulator-fixtures.cjs` refuses nonlocal hosts/non-test projects; `verify-property-runtime.cjs` requires separate loopback demo project/emulators and blocked outbound mail. Native `.test.cjs` fixtures use an isolated in-memory Firestore implementation; typecheck uses no database. Browser/full suites were not run.

`check-migration-readonly.cjs` loads local env and immediately reads live settings if configured; read-only still consumes quota. `storage-migration-inventory.cjs --live-readonly` scans up to 1,000 documents per collection with cursors (projection does not make document reads free). Live email/R2 scripts have explicit flags and can contact other providers; they were not run. Static audit scripts only parse source. No repository deployment scheduler definition established the actual cron cadence; external Cloud Scheduler, other deployments, consoles and credentials remain outside this audit.
